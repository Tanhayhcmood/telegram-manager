یک سیستم حرفه‌ای و تخصصی برای مدیریت خودکار گروه‌های تلگرام.

|------|---------|

| 🚀 عضویت | در شاخهٔ امن Render غیرفعال است |
| 📊 محدودیت | عضویت خودکار در شاخهٔ امن Render غیرفعال است |

## 🚀 راه‌اندازی محلی

### ۱. تنظیم محیط
```bash
cd telegram-manager
cp .env.example .env
# فایل .env را ویرایش کنید
```

### ۲. دریافت Session String (یک بار، فقط برای اجرای کامل محلی)
```bash
pip install telethon
python -m app.cli login
# کد دریافت‌شده را وارد کنید
# Session String را کپی کرده در TELEGRAM_SESSION_STRING بگذارید
```

### ۳. اجرا با Docker Compose
```bash
docker compose up -d
```

## ☁️ استقرار روی Render

شاخهٔ `render-safe-deployment` عضویت خودکار گروه‌ها و ارسال همگانی را به‌صورت سخت‌گیرانه غیرفعال می‌کند.
برای اجرای رایگان از webhook استفاده می‌کند. در Render، سرویس رایگان
پس از ۱۵ دقیقه بدون ترافیک ورودی می‌خوابد؛ ممکن است پاسخ به اولین پیام پس از بیکاری با تأخیر باشد.
PostgreSQL رایگان پس از ۳۰ روز منقضی می‌شود. این حالت برای اجرای دائمی یا داده‌های بلندمدت مناسب نیست.

متغیرهای `BOT_TOKEN` و `ADMIN_IDS` باید در Render تنظیم شوند. `WEBHOOK_SECRET` به‌صورت
خودکار تولید می‌شود و `DATABASE_URL` از PostgreSQL رایگان
Render می‌آید. این پیکربندی Redis جداگانه نمی‌سازد؛ وضعیت‌های موقت در حافظه‌اند
و با خواب یا راه‌اندازی مجدد سرویس از بین می‌روند.

مسیر `/healthz` فقط زنده‌بودن فرایند وب را گزارش می‌کند و برای health check خود
Render است. در شاخهٔ امن Render اتصال حساب کاربری Telethon خاموش است؛ بنابراین `/telegram/healthz` اتصال تلگرام را سالم گزارش نمی‌کند.
مسیر `/healthz` فقط زنده‌بودن سرویس وب را بررسی می‌کند و سرویس رایگان را همیشه بیدار نگه نمی‌دارد.

برای جبران لینک‌های جاافتاده، از منوی مدیر «بازخوانی لینک‌های جاافتاده» را انتخاب
کنید. این ابزار فقط تاریخچهٔ گروه‌هایی را که اکانت فعلی عضو آن‌هاست بررسی می‌کند،
پیام خصوصی را نمی‌خواند و گروه‌ها را عضو نمی‌شود. هر اجرا محدود به ۱۰۰ گروه،
۱۰۰ پیام برای هر گروه، ۵۰۰۰ پیام و ۱۰۰ لینک جدید است؛ اگر به سقفی برسد نتیجه را
گزارش می‌کند.

## ⚙️ تنظیمات مهم (`.env`)

در شاخهٔ امن Render، تنظیمات عضویت خودکار و کشف لینک فعال نیستند.

```env
# کشف فقط پیام‌های حاوی این کلمات (خالی = همه)
DISCOVERY_KEYWORDS=پیج,گروه,join

# حداکثر عضویت در روز
MAX_JOINS_PER_DAY=50

# تأخیر تصادفی بین عضویت‌ها (ثانیه)
JOIN_DELAY_MIN=240   # 4 دقیقه
JOIN_DELAY_MAX=480   # 8 دقیقه

# بکاپ روزانه (ساعت UTC)
BACKUP_DAILY_HOUR=3

# S3/Cloudflare R2 (اختیاری اما توصیه‌شده)
S3_BUCKET=your-bucket
S3_ENDPOINT=https://xxx.r2.cloudflarestorage.com
S3_ACCESS_KEY=xxx
S3_SECRET_KEY=xxx
```

## 🤖 دستورات ربات

| دکمه | عملکرد |
|------|---------|
| 📊 آمار | داشبورد آمار لحظه‌ای |
| 📋 لیست گروه‌ها | لیست با صفحه‌بندی ۱۵ تایی |
| ⏳ در انتظار | تایید / رد گروه‌ها |
| 🔴 ناموفق‌ها | گروه‌های join ناموفق + دکمه retry |
| 📨 ارسال | ارسال به یک یا همه گروه‌ها |
| 📢 ارسال همگانی | broadcast به گروه‌ها یا کاربران |
| 📥 خروجی | CSV گروه‌ها / CSV کاربران |
| 🚨 خطاها | آخرین ۲۰ خطای ثبت‌شده |
| 💾 بکاپ | دستی + لیست بکاپ‌ها |
| ❤️ وضعیت | سلامت client + صف |
| ▶️ / ⏹ | شروع / توقف user client |

## ⚠️ نکات مهم

1. **Session String** را هرگز commit نکنید — فقط در env var
2. **ADMIN_IDS** باید ID عددی باشد (از @userinfobot بگیرید)
3. در production حتماً **Redis** را فعال کنید (FSM پایدار)
4. اگر اکانت soft-ban شود، ربات فوراً هشدار می‌دهد
5. بکاپ‌های `/tmp` بعد از restart پاک می‌شوند — **S3 را حتماً تنظیم کنید**
